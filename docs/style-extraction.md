# 화풍 추출과 생성 검증

화풍은 묘사할 내용과 분리하면서도, 조형의 과장과 서투름까지 전달해야 합니다. 상세히 관찰한다는 이유로 생성 지시까지 장황해지거나, 그림을 정교하게 그리도록 바뀌어서는 안 됩니다.

## 여러 이미지로 비교하기

규칙 `2026-11-01.1`에서는 1~8장을 한 기록으로 등록할 수 있습니다. 합계 30MB까지이며, 각 이미지를 따로 최적화하고 원본은 저장하지 않습니다. 업로드 화면의 **기준으로** 버튼으로 첫 이미지를 바꿀 수 있습니다. 기록에는 전체 이미지와 순서, 비교 메모가 남고 재분석·외부 JSON에도 같은 묶음을 전달합니다. 기존 한 장짜리 기록은 데이터 변경 없이 연결 테이블을 보완합니다.

첫 이미지가 의도한 화풍의 기준입니다. 나머지는 반복되는 조형·선·면·명암·생략·마감을 확인하는 근거로 사용합니다. 특정 장면의 조명, 원근, 크롭, 의상색, 스캔 품질, 잘 보이지 않는 부위는 고정 화풍 규칙과 구분합니다. 서로 다른 화풍이 섞이면 기준 이미지와 맞는 특성을 유지하고 충돌하는 이미지 번호를 메모에 적습니다. 단순한 평균이나 모든 세부의 합집합으로 새 화풍을 만들지 않습니다. 중복 또는 비슷한 컷을 여러 독립 근거로 세지 않습니다.

여러 시점의 외형은 같은 캐릭터라는 근거가 있을 때만 합칩니다. 다른 인물이나 의상 상태는 나누며 보이지 않는 뒷면을 지어내지 않습니다. `reference_summary`는 한국어 공통점·차이·충돌과 비교 근거의 일치 여부를 담습니다. 생성용 화풍 본문에는 특정 이미지 번호나 비교 과정을 남기지 않아 독립적으로 재사용할 수 있습니다.

## 추출 순서

1. 작은 크기로 보아도 남는 조형과 비율을 먼저 찾습니다. 머리·몸통·사지·말단, 얼굴 안의 빈 공간, 눈의 가로/세로를 따로 봅니다.
2. 실력, 묘사량, 선의 자신감, 마감, 미형화 정도를 별개로 판정합니다. 단순해도 능숙한 그림과, 조형 자체가 서투른 그림을 구분합니다.
3. 이목구비의 구성 관계를 봅니다. 흰자·홍채·동공의 겹침, 눈꺼풀·코·입의 분리된 흔적까지 구체화합니다. 작은 눈을 점 눈으로, 큰 눈을 검은 타원 하나로 치환하지 않습니다.
4. 선·색면·명암·생략의 실제 작업 방식을 기록합니다. 없는 속눈썹·반짝임·블러시·주름·질감을 자동으로 보완하지 않게 합니다.
5. 인쇄·스캔·압축 흔적은 마지막에 다룹니다. 이런 흔적이 조형과 선의 차이를 대신하지 못하게 합니다.

## 선의 지문과 도구 추정

규칙 `2026-10-31.7`부터 여러 윤곽·내부선·끝점·접합부에서 아래 요소를 따로 관찰합니다.

- 선 내부와 가장자리: 불투명 잉크, 흑연 입자, 마른 붓의 이 빠짐, 번짐, 단단한 디지털 경계.
- 이어짐과 끊김: 한 번에 긋는 선과 짧게 잇는 선, 틈의 위치와 빈도, 해상도가 허용하는 범위에서 선 굵기에 대한 틈의 길이, 닫힘 누락.
- 겹침과 접합: 한 번 그린 윤곽과 탐색선·덧그림·수정선, 교차 꼬리, 삐침, 검게 뭉친 부분의 분포.
- 경로: 긴 직선·각진 면과 넓은 곡선·짧은 갈고리, 코너 전환, 흔들림의 크기, 마우스처럼 각지는 보정, 보정된 매끈한 곡선.
- 굵기: 외곽·내부·얼굴선의 상대 굵기, 필압 변화, 테이퍼, 둔하거나 둥근 끝, 사선 펜촉의 방향 변화.
- 재현 도구와 작업 방식: 원형 하드 브러시·일정한 굵기의 펜·유연한 펜촉·연필·펠트 팁·마른 붓·벡터 경로 등의 가능한 동작. 필압·손떨림 보정·래스터/벡터 같은 경계·선과 색면의 분리·페인트통 닫힘·정리 정도를 근거가 있을 때만 서술합니다.

프로그램이나 펜촉의 실제 정체를 이미지 하나로 확정하지 않습니다. 재현에 유효한 동작은 구체적인 지시로 쓰고, 추정의 한계는 한국어 관찰 메모로 남깁니다. 리사이즈·압축·안티앨리어싱을 펜촉의 흔적으로 오인하거나 정확한 펜 지름·브러시 설정·레이어 순서를 지어내지 않습니다. 선 없는 회화는 외곽선을 추가하지 않고 붓의 경계와 겹침을 설명합니다.

낙서용 짧은 실행 규칙에도 결정적인 선 특징을 2–4문장으로 남깁니다. 관찰 항목이 늘어나도 원본보다 선을 정돈하거나 질감·묘사를 추가하도록 유도하지 않습니다.

## 외부 도구용 JSON

새 분석에서 이미지를 고르거나 기존 기록을 연 뒤 **외부 도구용 JSON**을 누릅니다. Codex 계정 연결·CLI 실행·모델 호출 없이 현재 규칙과 이미지를 메모리에서 묶습니다. 새 이미지도 같은 WebP 최적화를 거치지만 원본·최적화본·요청문을 서버에 저장하거나 분석 대기열을 만들지 않습니다. 기존 기록은 이미 저장된 최적화본을 그대로 사용합니다.

화풍+캐릭터/화풍만/캐릭터만, 영어/한국어를 선택할 수 있습니다. JSON에는 `instructions`, `input`, `output_schema`, 적용 규칙 버전이 있습니다. 내부 엔진과 동일한 `build_prompt`와 응답 스키마, 참조 화풍 무시 문구, 낙서 실력 상한을 공유합니다. 외부 도구는 앱의 후처리가 없으므로 그 고정 문구를 최종 `style_prompt`에 직접 합치도록 추가 지시합니다. 추출 원본의 화풍을 분석하는 단계와, 추출 결과를 나중에 생성에 쓰는 단계도 명시적으로 구분합니다.

**이미지 포함**은 최적화한 WebP의 Base64 data URL을 담습니다. 한 장은 `input.image`, 여러 장은 순서를 보존한 `input.images` 배열과 `primary_image: 1`을 사용합니다. 도구가 해당 데이터를 이미지로 해석해야 합니다. 일반 대화창에서 인식하지 못하면 **이미지 별도 첨부**로 전환해 한 장은 `reference.webp`, 여러 장은 `reference-01.webp`부터 표시된 모든 이미지를 순서대로 첨부합니다. 요청문 복사·JSON 다운로드·첨부용 이미지 다운로드를 제공하며, 클립보드 권한이 없으면 직접 선택해 복사할 수 있습니다.

특정 업체의 API에 그대로 보내는 HTTP 본문이 아니라 멀티모달 도구에 전달할 공통 요청 명세입니다. API 연동 시 해당 도구의 이미지/지침/응답 스키마 필드에 맞춰야 합니다. 같은 추출 원칙과 구조를 전달하지만 도구와 모델에 따라 실제 프롬프트는 달라집니다. 로그인 쿠키·서버 경로·계정 인증 정보는 포함하지 않습니다.

## 낮은 실력을 보존하는 방식

`style_execution`을 `raw_awkward`, `controlled_sparse`, `confident_graphic`, `painterly`로 구분합니다. 이는 원본의 조형을 기준으로 한 분석 결과이며 생성 이미지의 해상도 설정이 아닙니다.

`raw_awkward`일 때는 모델이 별도로 작성한 짧은 `raw_style_recipe`를 사용합니다. 앱이 낮은 그림 실력과 마감을 상한으로 삼는 고정 문구를 붙입니다. 긴 일반 화풍 설명을 그대로 사용하는 대신, 덩어리의 불균형·좁은 연결부·어색한 작은 얼굴 흔적·비어 있는 면·일정한 색면을 실행 규칙으로 압축합니다. 회화체와 능숙한 만화체에는 이 문구를 적용하지 않습니다.

화풍만 선택하면 캐릭터용 비율 중립화 지침을 모델에 보내지 않습니다. 캐릭터만 선택하면 화풍 지침을 보내지 않습니다. 둘 다 선택한 경우에도 두 출력의 역할을 명확히 분리합니다.

## 참조 이미지의 역할

`style_contract.py`의 고정 문구가 생성용 화풍 프롬프트 앞에 붙습니다. 참조 이미지는 정체성·외형·의상·사물·포즈·구도 등 내용만 제공하며, 참조의 화풍은 완전히 무시합니다. 조형 변형·비율·선·채색·명암·생략·실력·마감은 텍스트 화풍만 따릅니다.

기존 기록을 조회할 때도 이 규칙을 붙입니다. 원래 분석 본문은 DB에 보존하며, 이미 붙어 있거나 이전 버전의 문구가 있으면 중복으로 쌓지 않습니다. 새 분석과 재분석에는 `engine.style_ruleset`으로 적용 버전을 남깁니다.

이 규칙은 생성기에 전달하는 명시적 지시입니다. 다른 이미지 생성기의 해석이나 참조 이미지의 영향을 완전히 통제하는 기능은 아닙니다.

## 회귀 검증

`tools/style_regression.py`는 저장된 세 원본에 기존 기록과 같은 모델·추론 단계로 추출을 실행합니다. 각 실행의 프롬프트 해시, Codex 버전, 시간, 결과 JSON과 Markdown을 남깁니다. 생성 비교에는 같은 새 장면을 사용합니다.

`tools/build_style_report.py`는 원본·기존 프롬프트 생성물·수정 프롬프트 생성물·중간 실험을 나란히 보여주는 HTML을 만듭니다. 생성 이미지는 편집하지 않습니다. 별도의 회화체 내용 참조를 붙여 거친 화풍 텍스트만 적용하는 상충 시험도 수행합니다.

내장 Image Generation 도구는 정확한 모델·시드·출력 크기를 고정할 수 없습니다. 비교는 통계적인 재현율이 아니라 관찰 검증입니다. 사용자 고유의 캐릭터 디자인과 특수한 장면을 화풍 규칙에 복사하지 않기 때문에, 새 내용에서 원본과 동일한 인상을 보장하지는 않습니다. 그림의 구조·정보량·선과 색면·과잉 마감 여부를 각각 확인합니다.

실험 자료는 운영 서버 `/data/experiments/style-rules-v6/`에 보관하며 작업실 로그인 뒤에만 조회할 수 있습니다. 검증한 프롬프트는 기존 세 기록을 덮어쓰지 않고 별도 기록으로 추가합니다.
